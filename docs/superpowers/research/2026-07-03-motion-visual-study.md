## Method note (TEMPORAL surface)
Motion is temporal; you cannot curl a timing curve. This board pins **representative stills of motion
work** and describes the timing/feel in prose. Two source classes were combined deliberately:
**(a) film FUI** (GMUNK's *Oblivion*, Ash Thorp's *Call of Duty: Infinite Warfare*) for the *motion
vocabulary* — decrypt, boot-assembly, scan-in-progress, lock states, motion-echo, restraint; and
**(b) Codrops web demos** for the one thing stills can't give — **published, measured timing values**
(GSAP stagger/duration/easing, cursor lerp constants, glitch `steps()`), quoted from the tutorials'
own code. Every timing number here is either **[EXTRACTED]** (published in a primary source, quoted) or
**[WORKING]** (my inference from a still). **No timing is tagged [DATA]** — none was self-measured
frame-by-frame, consistent with the library's standing "hologram/motion timing" open debt. Nothing invented.

**Host feasibility (validated this surface):** ✅ `codrops-1f606.kxcdn.com` (Codrops KeyCDN — featured images
curl clean), ✅ `i0.wp.com` (WordPress Photon — GMUNK *Oblivion* stills via ilikeinterfaces.com),
✅ `images.squarespace-cdn.com` (Ash Thorp COD via HUDs+GUIS, re-confirmed from globe surface).
Codrops article HTML reads fine via WebFetch and **publishes real timing numbers** — the highest-value
web source. ❌ `interfaceingame.com` returns **403** to WebFetch (Cloudflare, like ArtStation) — CP2077

(his COD work came through HUDs+GUIS). `awwwards.com` not captured (no validated direct-image host; the

## Principles
Tier legend: [VERIFIED] cross-checked across ≥3 board refs · [EXTRACTED] read/quoted directly off one primary source (incl. timing numbers published in a tutorial) · [DATA] self-measured value (none here — temporal surface) · [WORKING] practitioner judgment/inference from a still, no measured source.

1. [EXTRACTED] **Entrances ease OUT, exits ease IN, on a tight stagger.** Codrops' text-reveal publishes the exact recipe: `staggerValue: 0.014` (14 ms between letters), `charsDuration: 0.5` (500 ms/char), entrance `Power3.easeOut`, exit `Power3.easeIn`, background cross-fade `0.8` s `Power1.easeInOut`. The felt law: things *arrive* fast-then-settle (ease-out) and *leave* slow-then-accelerate (ease-in); siblings fire on a small constant delay. **Site bears:** `effects.js` already sets `--d = i*0.07s` (70 ms stagger) and eases counters with cubic ease-out (`1 - pow(1-p,3)`) — on-idiom; the ref says per-letter text staggers can go far tighter (~14 ms). (ref: 001-codrops-stagger-reveal; src: https://tympanus.net/codrops/2020/06/17/making-stagger-reveal-animations-for-text/)

2. [VERIFIED] **Acknowledge a state change with ONE boxed keyword, not a sentence.** The "system is responding" signal is a single verb in a bracket that snaps in at the moment of change: COD `LOCKED` (002, 017), GMUNK `TERMINATE` (005), mode banners `SCANNING MODE` / `TACTICAL MODE` (004, 005). Cross-checked across four frames — never a paragraph, never a toast. **Instruction:** on an interaction/section change, flash one boxed state-word (`LOCKED`, `LIVE`, `SYNCED`) that animates in then holds. **Site bears:** `boot.js` already emits `<ok>OK</ok>` / `<warn>LIVE</warn>` tags — extend that grammar to hover/scroll feedback. (ref: 002-thorp-cod-reticle, 005-gmunk-target-track, 017-thorp-cod-hud-overview; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)

3. [VERIFIED] **Render a fast/refreshing value as a chromatic ghost-echo, not a motion blur.** Ash Thorp stamps "PLAYER 01 / 9939.3" as **2–3 discrete offset duplicates** — one lead copy plus trailing red/blue channel-shifted ghosts a few px off. Cross-checked across three COD frames (002, 003, 017); it reads as "this readout is updating faster than the eye." **Instruction:** for a rapidly-changing number or a streaking element, draw a short stack of offset, channel-split copies rather than a Gaussian smear. **Site bears:** `effects.js` scramble and the `cursor.js` trail could adopt a 2-copy chromatic echo on rapid change. (ref: 002-thorp-cod-reticle, 003-thorp-cod-data-build, 017-thorp-cod-hud-overview; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)

4. [EXTRACTED] **Decrypt resolves glyph-by-glyph in a fixed-width/dot-matrix face.** GMUNK renders "ANOTHER DAY IN PARADISE" mid-formation in an LED dot-matrix (006): characters swap in place from noise to signal with **no reflow**, because the face is monospaced. **Instruction:** run any scramble/decrypt in a mono face so glyphs settle in place; resolve left-weighted so the eye tracks completion. **Site bears:** `effects.js window.scramble` (700 ms, per-char settle 0.2–1.0 of progress) and `boot.js` decrypt (14 frames × 38 ms ≈ 530 ms) already do exactly this — the ref validates the aesthetic (dot-matrix) and the in-place per-glyph settle. (ref: 006-gmunk-decrypt; src: https://ilikeinterfaces.com/2015/04/21/ui-review-oblivion/)

5. [EXTRACTED] **The cursor trails by a per-frame lerp (~0.2 of the gap), not a timed tween.** Codrops' custom-cursor code interpolates `lerp(last, target, 0.2)` — the ring moves 20 % of the remaining distance every frame, so it lags on fast moves and catches up organically; hover scales the cursor `1.08`, leave `0.92`. **Instruction:** keep the reticle on a frame-rate lerp in the 0.15–0.2 band — never a fixed-duration ease, which feels robotic on erratic input. **Site bears:** `cursor.js` already lerps at `0.18` (`rx += (mx-rx)*0.18`) — the reference confirms the constant is on-idiom, and suggests adding the `1.08`/`0.92` hover-scale beat. (ref: 014-codrops-cursor; src: https://tympanus.net/codrops/2019/01/31/custom-cursor-effects/)

6. [EXTRACTED] **Magnetism = the element and cursor ease toward each other inside a proximity radius.** The frozen magnetic-button frame (015) shows the soft cursor blob pulled *off-center into* the `Confirm` button — the button is the attractor, the pointer yields. **Instruction:** on `[data-magnetic]` targets, translate both the element toward the pointer and hold the cursor slightly captured, released on `pointerout`. **Site bears:** `cursor.js` already pulls magnetic elements by `0.28` of the offset (`dx = (mx-cx)*0.28`) and clears on exit — matches the demo; consider also nudging the ring toward the element center for the mutual-attraction read. (ref: 015-codrops-magnetic; src: https://tympanus.net/codrops/2020/08/05/magnetic-buttons/)

7. [VERIFIED] **Animate the focus only; leave the field dead still — this is *when not to animate*.** GMUNK's *Oblivion* brief was explicitly "functionality and minimalism," and it shows: the light-table is a dark map with a *few* glowing markers (008), the cockpit HUD is a **faint** vector reflection on glass that never competes with the flight (009), and the COD HUD composited over a live lunar plate (017) keeps 90 %+ of frame un-lit. Cross-checked across three frames. **Instruction:** motion is a scarce signal — animate the one thing that changed; do not idle-animate chrome, backgrounds, or every card. Restraint reads as competence. **Site bears:** governs *everything* in `effects.js`/`cursor.js` — the scene-ping cooldown (600 ms) and reveal-once (`splice` after `seen`) already ration motion; keep that discipline. (ref: 008-gmunk-lighttable, 009-gmunk-bubbleship-hud, 017-thorp-cod-hud-overview; src: https://ilikeinterfaces.com/2015/04/21/ui-review-oblivion/)

8. [EXTRACTED] **Signal an escalation with a hue jump, not more motion.** The identical *Oblivion* drone HUD is **amber** in `SCANNING MODE` (004) and **red** in `TACTICAL MODE`/`TERMINATE` (005) — the geometry barely changes; the color carries the state. **Instruction:** reserve a warning color (amber→red) for genuine escalation; a palette shift communicates "state changed" more cheaply and legibly than adding animation. **Site bears:** pairs with the design language's cool-instrument / warm-signal split — a section or control entering an "active/alert" state should shift accent hue, not start moving. (ref: 004-gmunk-drone-scan, 005-gmunk-target-track; src: https://ilikeinterfaces.com/2015/04/21/ui-review-oblivion/)

9. [EXTRACTED] **Cross-cut sections with opposing-direction slides + a micro rotation settle.** The reveal frame (001) catches the home headline exiting `y: -100%` (up/out) while the about card enters `y: 100% → 0` (from below) with `rotation: -4 → 0` and `opacity: 0 → 1`, all around `0.8` s. The overlap — one thing leaving up as another arrives from below — reads as a physical cut, not a fade. **Instruction:** for section transitions, move outgoing and incoming content in *opposite* directions and let the incoming element settle out of a 3–4° tilt. **Site bears:** `effects.js` reveals currently add a single `.seen` class (clip/opacity) — this ref is the upgrade path toward directional, paired reveals. (ref: 001-codrops-stagger-reveal; src: https://tympanus.net/codrops/2020/06/17/making-stagger-reveal-animations-for-text/)

10. [EXTRACTED] **Glitch = stepped channel-split + horizontal slice displacement, kept short.** Codrops' glitch runs layer animations on `var(--time-anim) infinite linear alternate` with a final-layer `flash 0.5s steps(1,end) infinite`, driving each channel by `translate3d(±gap,0,0)` and revealing horizontal bands via `clip-path: polygon(...)` keyframes stepped at 10 % stops (012 shows exactly this: RGB fringes + a sliced offset band). The `steps()` (not smooth) timing is what makes it read "digital." **Instruction:** build glitches from stepped (not eased) channel offsets + clip-path slices; keep them sub-second and reserve them for transitions/errors, never idle decoration. **Site bears:** the globe/HUD already carry chromatic aberration — a *stepped* variant is the transition-glitch primitive. (ref: 012-codrops-glitch; src: https://tympanus.net/codrops/2017/12/21/css-glitch-effect/)

11. [EXTRACTED] **"Live" is sold by never fully settling.** GMUNK's signal panel (007) keeps a waveform scrolling and dotted data-rows streaming even at idle — the readout micro-updates without demanding attention. **Instruction:** idle telemetry (clock, coordinates, a trace) should perpetually micro-move — jitter the last digits, scroll a 1-px waveform — so the interface reads as a live instrument, not a static mock. **Site bears:** `effects.js` live Tokyo clock (`setInterval 1000`) is the seed of this; a subtly animated coordinate/trace in the HUD would extend it (respecting `prefers-reduced-motion`, which the file already checks). (ref: 007-gmunk-decrypt-signal; src: https://ilikeinterfaces.com/2015/04/21/ui-review-oblivion/)

12. [EXTRACTED] **Fields boot from a placeholder to a value.** COD boot screens fill with `88` seven-segment placeholders (all segments lit = "no data yet") and `LOAD` tokens (016, 018) that resolve into real numbers as the system comes up. **Instruction:** numeric readouts should initialize as `88`/`LOAD`/`--` and *resolve* into their value (count-up or decrypt), so first paint reads as "powering on," not "empty." **Site bears:** `boot.js` already ramps a progress bar and `effects.js` counts `[data-count]` up with ease-out — unify them: seed counters at `88`→value on reveal. (ref: 016-thorp-cod-boot, 018-thorp-cod-bootframe; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)

13. [VERIFIED] **The custom cursor's native metaphor is an acquiring reticle.** Across the targeting frames the cursor-analog is an instrument that *acquires*: concentric lock ring + corner ticks (002), a rangefinder tick-ruler tracking a subject (010), a circular scope tightening on a target (011). Cross-checked across three frames. **Instruction:** the site's reticle cursor should *acquire* on hover — brackets snap inward / a ring tightens / a range-tick appears — rather than merely recoloring. **Site bears:** `cursor.js` has `is-hot`/`is-down`/`is-text` classes and a lerped ring; add a "tighten/snap" transform on `is-hot` to complete the reticle read. (ref: 002-thorp-cod-reticle, 010-gmunk-scope-reticle, 011-gmunk-combat-target; src: https://ilikeinterfaces.com/2015/04/21/ui-review-oblivion/)

14. [WORKING] **Fire reveals slightly BEFORE the element is centered, so motion finishes as it lands.** No board source measures the ideal scroll trigger (film frames are not scroll-driven), so this is practitioner judgment, not measured. The site currently triggers at `top < vh * 0.92` (element 8 % into the viewport). Reading the reveal demo (001), a reveal that *completes* around the moment the element reaches comfortable reading height feels "already settling" rather than "popping in late." **Instruction:** trigger reveals ~8–15 % into the viewport (keep the current 0.92 threshold or tune slightly earlier), and keep durations short (≤ ~0.8 s) so the animation resolves before the element is centered. (ref: 001-codrops-stagger-reveal; src: https://tympanus.net/codrops/2020/06/17/making-stagger-reveal-animations-for-text/)

## Thin areas / open questions
- **No self-measured [DATA] timing.** Every number here is either published-in-source ([EXTRACTED]: 001, 012, 014) or inferred ([WORKING]: 014-threshold). A true [DATA] pass would require frame-stepping a reel (GMUNK/Thorp Vimeo) against a timer — deferred, and consistent with the library's standing "hologram/motion timing" open debt.
- **Spring vs ease-out feel is unresolved.** The extract target asked for ease-out *vs spring*; every measured reference found is GSAP `Power`/ease-out (no overshoot/spring constants published). Whether daikieOS wants a subtle spring/overshoot on any beat is currently [WORKING] — untested against a source.
- **Awwwards not directly captured.** No validated direct-image host for awwwards portfolio media (JS-gated). The web-interaction requirement is met via Codrops demos, which additionally carry the measured values a screenshot would lack — arguably a stronger substitution, but a literal Awwwards "magnetic cursor" showcase remains uncaptured.
- **gmunk.com + interfaceingame blocked.** `gmunk.com` is JS-gated (WebFetch could not enumerate image URLs); GMUNK *Oblivion* was sourced via the ilikeinterfaces.com mirror (i0.wp.com) instead — if a first-party GMUNK frame is ever needed, use the MCP-browser screenshot fallback. `interfaceingame.com` returns 403 to WebFetch (Cloudflare), so the CP2077 scan/particle-assembly frames were not captured here; that specific "particle assembly on scan" motion is covered conceptually by the GITS solograms in the globe board plus GMUNK's scan-in-progress (004).
- **Stills can't show acceleration.** Curve *shape* (how ease-out an ease-out is) is inferred from published names, not seen. The elevation brief should treat all curve specifics as tunable, validated in-browser, not as fixed law.
