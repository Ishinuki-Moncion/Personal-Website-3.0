## Method note
Discovery via WebSearch/WebFetch for direct image URLs → `tools/refcap.sh hud` (curl + sips) → `Read`.
**Host feasibility (informs later surfaces):** `interfaceingame.com` — the plan's key untested source — returns
**HTTP 403 to WebFetch** (Cloudflare page-gate, same failure class as artstation.com); it could not be enumerated,
so it is NOT usable via curl/WebFetch. Fell back to the proven hosts. ✅ curl-able with browser UA:
`images.squarespace-cdn.com` (HUDs+GUIS hosts BR2049 / Cyberpunk 2077 / COD:IW / Halo Wars 2 FUI there),
`territorystudio.com/wp-content` (The Martian), `upload.wikimedia.org` (real aircraft-HUD + oscilloscope).
One quirk: squarespace serves **WebP bytes under a `.jpg` URL** — `Read` renders them fine, but `sips -Z` can't
re-encode them (harmless: files are already small, ~16–560 KB). No MCP browser fallback was needed.
Board leans on film/game FUI (Territory Studio, Ash Thorp) for the "chrome grammar" half and real instruments
(F/A-18 combiner HUD, analog oscilloscope) for the non-fiction ground truth of tick systems + single-hue readouts.

## Principles
Tier legend: [VERIFIED] cross-checked across >=3 board refs · [EXTRACTED] read directly off one primary reference · [DATA] measured pixel value · [WORKING] practitioner judgment/extrapolation, no measurement.

1. [VERIFIED] **One ink, one accent.** Render the entire HUD in a SINGLE hue over the dark (green, off-red, or cyan) and reserve exactly ONE contrasting accent for asserted state (lock / alert / active) used on only a handful of marks — never a third colour for decoration. Cross-checked: real F/A-18 (all green), oscilloscope (green trace), Cyberpunk (off-red), Ash Thorp COD (one teal field + one red-orange accent). For daikieOS: hold the cyan-instrument / amber-signal split from the globe study and let nothing else tint. (ref: 007-cp2077-hud, 020-fa18-hud-real, 021-fa18-gun-symbology, 022-oscilloscope-graticule, 010-cod-hud-002; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)
2. [VERIFIED] **Restraint is the effect — keep the field mostly empty.** The active "ink" should occupy a small fraction of the frame; the centre is left for the world/content and marks retreat to the edges and the reticle. Ash Thorp's HUD is ~95% empty and still reads as a complete instrument; it survives composited over a moonscape and over black unchanged. A HUD that fills its frame reads as noise, not signal. (ref: 010-cod-hud-002, 011-cod-hud-008, 019-martian-airlock, 002-br-wsp-panel2; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)
3. [VERIFIED] **Frame with thin corner brackets, never a full box.** Imply the live area with L-shaped corner brackets set slightly in from the edge; restraint completes the rectangle the eye infers. Cross-checked across Cyberpunk's screen corners, COD's bracket-bounded reticle zone, and BR2049's ticked frame border — none draws a closed border. (ref: 007-cp2077-hud, 011-cod-hud-008, 004-br-b-screen; src: https://www.hudsandguis.com/home/2019/cyberpunk-2077)
4. [VERIFIED] **Label + value + unit as a tight triad, value dominant.** Set an abbreviated label (a single glyph or 2–3 caps), the value, and a small/subscript unit on one mono baseline so the VALUE is the largest element: real HUD "α 20.3 / M 0.36 / G 1.7", BR "S/E 27403.164", COD "93.9" over a tiny "94." unit. Abbreviate the label to the point of glyphs; never let the unit outweigh the number. (ref: 021-fa18-gun-symbology, 005-br-m-screen, 012-cod-hud-014; src: https://commons.wikimedia.org/wiki/File:F-18_HUD_gun_symbology.jpeg)
5. [VERIFIED] **Bracket tags assert live state.** Wrap a status word (LOCKED, ARMED) or a designated value in a thin rectangular bracket to mark it active — the outline box IS the signal, never a filled chip. Cross-checked: COD's "LOCKED" pill, the real F/A-18's boxed heading/target values, BR2049's bracket-box target markers. (ref: 010-cod-hud-002, 021-fa18-gun-symbology, 004-br-b-screen; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)
6. [EXTRACTED] **Offset the label, bridge the gap with a leader.** Never overlap a label on its subject — push it into empty space and connect with a thin or dotted leader line. Cyberpunk's TROUBLESHOOTING list runs each code to its value on a dotted leader; BR2049's orbit nodes throw tangent leader lines out to a labelled apex. The leader keeps the subject clean and the label legible. (ref: 007-cp2077-hud, 002-br-wsp-panel2; src: https://www.hudsandguis.com/home/2019/cyberpunk-2077)
7. [VERIFIED] **Lay the data on a low-contrast tick/graticule substrate.** Under the readouts, pitch a measured grid — major divisions plus subdivided minor ticks — dimmed well below the data so it gives alignment and scale without competing. Ground truth: the oscilloscope's major-grid + minor-tick axes and the F/A-18 pitch ladder / heading tape; echoed by COD's field of tiny cross-ticks and BR's faint grid. (ref: 022-oscilloscope-graticule, 020-fa18-hud-real, 010-cod-hud-002; src: https://commons.wikimedia.org/wiki/File:Sine_wave_10_kHz_displayed_on_analog_oscilloscope.jpg)
8. [EXTRACTED] **Multi-panel: lock every readout to a shared rectilinear grid, size by priority.** When many readouts coexist, give each a bounded panel with a labelled title bar, align them to one grid, and let importance set size — hero panel centre, telemetry ringing the margins. The Martian's mission-control screens are a strict grid of titled panels (MICROSCOPE FEED / COMMUNICATIONS / RADIOMETER / TELEMETRY), never free-floating. (ref: 017-martian-panel1, 018-martian-panel2; src: https://territorystudio.com/project/the-martian/)
9. [EXTRACTED] **Time-varying data is a trace, not a digit.** For anything live, show the waveform/line over its grid — the moving line IS the information — rather than a static number. Halo Wars' "INCOMING AUDIO SIGNAL" and the oscilloscope both make the trace the hero; The Martian's LASER panel uses a mini-graph. (ref: 015-hw2-audiosignal, 022-oscilloscope-graticule; src: https://www.hudsandguis.com/home/2018/halowars2-ui-supercut)
10. [VERIFIED] **Tabular mono numerals: fixed-width, right-aligned, slashed capacities.** Set all numbers in a tabular monospace so columns align digit-for-digit; use the "current/max" slash form (25/200) for capacities and keep decimal places fixed. Seen across The Martian's dense tables, the real HUD's fixed-decimal values, and COD's ratio readouts. (ref: 017-martian-panel1, 021-fa18-gun-symbology, 010-cod-hud-002; src: https://territorystudio.com/project/the-martian/)
11. [VERIFIED] **Build the reticle from detached ticks, with a gap at true centre.** Assemble the crosshair from small separated strokes, a thin ring, and directional chevrons — legibility from arrangement, not stroke weight — and leave the exact centre open so it never occludes the target. COD's reticle, the real flight-path marker (ring + wings), and the oscilloscope centre-cross all keep the middle clear. (ref: 010-cod-hud-002, 012-cod-hud-014, 020-fa18-hud-real; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)
12. [WORKING] **Projection texture belongs on the content layer, not the chrome.** Scanlines, grain, chromatic split, and glitch sell "this is a projected/scanned display" — but apply them to the imagery/scan layers and keep the interactive chrome (labels, reticle, brackets) crisp, or legibility dies. BR2049's monitor scans are heavily scanlined while their overlaid data stays sharp; COD shows only a whisper of RGB split on its marks. Degree is a judgment call, hence WORKING. (ref: 003-br-ljo-panel, 007-cp2077-hud; src: https://www.hudsandguis.com/home/2018/blade-runner-2049)
13. [VERIFIED] **Ground the HUD in worn hardware where it meets an edge.** Imply a physical housing — bezel, combiner glass, labelled buttons — rather than a floating flat rectangle: BR2049's monitor with its V2/EV/AM/REC button rail, the F/A-18's glass combiner inside the canopy frame, the oscilloscope's graticule glass and CRT bezel. Consistent with the globe study's "future-as-worn-hardware" instrument principle. (ref: 003-br-ljo-panel, 020-fa18-hud-real, 022-oscilloscope-graticule; src: https://commons.wikimedia.org/wiki/File:Hud_on_the_cat.jpg)
14. [WORKING] **Design two densities: a calm resting state that blooms into an engaged state.** Ash Thorp's HUD is near-empty at rest (010/012) and swells into a dense teal scope when engaged (013); The Martian's mission control is the full-density extreme. The chrome should breathe — minimal by default, instrumented on scan/interaction, then collapse back. This is a behavioural extrapolation (the transition is the motion surface's job), hence WORKING. (ref: 010-cod-hud-002, 013-cod-hud-020, 017-martian-panel1; src: https://www.hudsandguis.com/home/2016/11/29/cod-infinity-warfare-ui)
15. [EXTRACTED] **Fill the "void" with a dim data-texture substrate, not flat black.** Give the background a very-low-contrast instrumented texture — contour lines, an orbital plot web, a scrolling ticker column — so the field reads as measured space rather than emptiness, while staying dim enough that foreground marks dominate. Halo Wars' topographic field and astro-nav web, and The Martian's orbital arcs, all instrument their negative space. (ref: 016-hw2-holotable, 014-hw2-astronav; src: https://www.hudsandguis.com/home/2018/halowars2-ui-supercut)

## Bearing on daikieOS chrome (no code this phase)
The site's HUD chrome lives in `css/site.css` + `js/app.js` + `js/effects.js`. These principles bear on it as follows (exact line-level levers deferred to the Task 9 elevation brief): P1/P4/P10 → the section labels, readouts and any numerals set in the frame chrome; P3/P11 → the existing corner-frame and any reticle/scan cursor; P2/P7 → the control-deck and scroll-HUD (keep them sparse, seat them on a faint tick grid); P13 → the lightbox/frame edges (imply housing, not a flat card); P12/P14 → the boot sequence and scan interactions (texture the scanned content, breathe between calm/engaged). No code is changed here.

## Thin areas / open questions
- **No [DATA] measurements.** Restraint ("well under ~5% ink"), tick pitch, accent-coverage ratio, and scanline density are all qualitative ([VERIFIED]/[EXTRACTED]/[WORKING]); a [DATA] pass would need a pixel picker / coverage count on a frame. Consistent with the library's standing "no hologram/HUD measurement" open debt — not invented here.
- **interfaceingame.com is unusable via curl/WebFetch (HTTP 403 Cloudflare).** The plan's priority game-UI archive could not be enumerated; coverage of Cyberpunk/Deus Ex/Destiny/Death Stranding leaned on the HUDs+GUIS squarespace mirror instead. If a later surface truly needs interfaceingame, it will require the MCP-browser fallback (untested here).
- **ashthorp.com / gmunk.com direct portfolios untested.** Ash Thorp material was reached via the HUDs+GUIS COD:IW page, not ashthorp.com; GMUNK was not captured this surface (his globe/Oblivion work is more globe-surface anyway). Direct-host curl-fetchability of both remains unproven.
- **Motion is out of frame.** P9 (live trace), P14 (calm→engaged bloom), and any "system responding" feedback are pinned as stills; their *timing/easing* is the motion surface's job and is marked WORKING where it touches behaviour.
- **Two densities is an extrapolation.** No single ref shows the same HUD transitioning between its calm and engaged states in one frame; P14 infers the pair from separate stills (010/012 vs 013) plus the mission-control extreme (017).
