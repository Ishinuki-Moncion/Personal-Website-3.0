Why an AI needs the rules written down

Every production team has rules that live in people's heads. What the ad platform rejects. How a click must be wired. What a format needs before it can ship. A new colleague learns them over months.

An AI starts from nothing every time you open a new conversation with it. So the rules have to be written down, for a reader that follows them literally and cannot ask what you meant.

What the kit holds

The kit is a set of documents that an AI agent loads when a task needs them. An agent is an AI that uses tools to carry out a task step by step. It holds the hard rules, one page per ad format with starter code, the design values, a quality checklist and the delivery rules.

Every rule has a stable ID. Other tools cite the ID instead of copying the words, and a test fails when a cited rule no longer exists. A rule copied into three places becomes three rules that drift apart.

Code checks what code can check

Some rules can be checked by code, so they are. A gate, which is an automatic check, reads a finished build and passes or blocks it. The other rules stay as written guidance.

Keeping the two apart keeps the gate honest, because it only claims what it actually tests. It also keeps the written rules short enough to read.

A test before building on something new

The company's ad editor gained an AI connector: a way for an AI to build ads directly inside the editor. The obvious move was to load the whole kit into every session that used it. I tested that idea first.

Fresh AI sessions built the same orders. They differed in one thing only: what they had beside the connector. That was nothing, one page of rules, a trimmed kit, or the full kit. I timed and scored every run.

The result changed the plan. With the connector alone, the AI repeated the same faults every time. One page of rules fixed most of them at almost no extra cost. The full kit did not make a better first draft. It added proof: a checked build and a record.

So I shipped the one-page rule card, with a test that fails if the kit changes and the card does not. I also split jobs into three kinds: pitch, draft and delivery. A pitch no longer pays for delivery checks.

Keeping up with a fast-changing tool

The connector changed its document format several times in one week. A written description of it would have gone stale before anyone noticed.

So the kit keeps a dated record of how the connector works. Before it builds, an AI session compares that record with the live connector. If they disagree, the session says so instead of building on old information.

How it fits with Night-Shift Studio

The kit is one half of a system. It holds the rules. Night-Shift Studio is the overnight pipeline that follows them, and the team's daytime tools read the same kit.

Each Night-Shift release is paired with a kit release. A rule changes in one place, and every tool picks up the change in a planned release.
