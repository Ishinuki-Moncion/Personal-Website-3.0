The problem is repetition

Finding an apartment in Tokyo on a fixed budget, in certain wards, near certain stations, is not a hard search. It is the same search, every day, for weeks.

The cost is remembering to run it, and noticing what changed since yesterday.

So the goal was to take me out of the repetition but keep me in the decision. A scheduled run does the whole search and produces a summary. Adjusting the criteria and reading the results is all that is left for me.

A local tool, on purpose

It runs on one computer for one person. There is no hosting, no account, and no data leaves the laptop. For a search about where someone will live, that is the right default.

You start it by double-clicking a launcher that opens a browser page. If the usual port is taken, the local server picks a free one.

It shuts itself down a few minutes after the last tab closes, but never during a run. Software on your own computer should not need remembering or a manual shutdown.

Two languages, each rendered whole

The interface is in Japanese and English, and it remembers your choice. The server renders each page in the chosen language. It does not ship both and switch in the browser, and it does not use machine translation.

That matters for housing. Japanese listing terms are precise: deposit and key money, the guarantor arrangement, the stove type, the move-in window. Where a term is a term, it stays in Japanese in both versions.

Comparing, and watching change

Results appear in a filterable table that remembers what you have seen, so a dismissed listing stays dismissed.

Favourites open side by side, grouped by what decides these choices: cost, commute and location, and the property itself. That includes details that are easy to miss until move-in.

Every run is kept, so the tool also shows how prices and availability move over time. One run shows what is on the market. The history shows whether waiting is working.
